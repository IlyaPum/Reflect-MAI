# PRODUCT.md — Единый продуктовый контекст проекта

> **Название (рабочее):** MAI Navigator (навигатор по кампусу МАИ без GPS)
> **Статус:** прототип / MVP
> **Этот файл — единственный источник правды о продукте.** Любое проектирование, генерация кода и принятие решений по архитектуре сверяются с ним. При изменении продукта файл обновляется.

---

## 1. Суть продукта

Автономный офлайн-навигатор для студентов МАИ, который:

1. **Определяет местоположение без GPS/ГЛОНАСС и без интернета** — по фотографии здания (visual place recognition) и датчикам движения телефона (шагомер + компас).
2. **Ведёт пользователя к цели** — пользователь не просто узнаёт, где находится, а спрашивает: *«Как дойти до корпуса 1?»* — и получает маршрут по территории кампуса.
3. **Работает целиком на устройстве** — один APK, ни одного запроса в сеть во время использования.

### Проблема
- Внутри зданий, в переходах и в условиях плохого приёма GPS-точка «плавает» или пропадает.
- Студент-первокурсник не знает, где какой корпус (у МАИ 8+ учебных корпусов, разнесённых по территории).
- Обычные карты требуют интернет и не знают внутренних корпусов/маршрутов кампуса.

### Ключевая ценность
> Снял здание камерой → приложение узнало фасад → сказало, где ты → построило маршрут до нужного корпуса → ведёт по маршруту стрелкой, двигая метку шагомером, даже когда телефон в кармане и спутников нет.

## 2. Пользовательские сценарии (MVP)

### Сценарий A — «Где я?» (первичная засечка)
1. Пользователь открывает приложение, видит карту кампуса МАИ без своей позиции.
2. Нажимает большую кнопку камеры, наводит на ближайшее здание, делает снимок.
3. Нейросеть узнаёт фасад → позиция ставится на карту с ореолом точности (стягивается к координатам здания из EXIF-базы).

### Сценарий B — «Веди меня до корпуса» (главный сценарий продукта)
1. После засечки пользователь выбирает цель: «Корпус 1», «Корпус 8», «Столовая», «Главный вход» (выбор из списка POI кампуса).
2. Приложение строит пешеходный маршрут по графу дорожек/проходов территории МАИ от текущей позиции к цели.
3. Стрелка пользователя движется по маршруту в реальном времени за счёт шагомера и компаса; счётчик остатка дистанции уменьшается.
4. При накоплении погрешности (радиус неопределённости > порога) приложение просит: «Сфотографируйте ближайшее здание для уточнения». Новый снимок заново привязывает позицию.
5. Приход к цели: уведомление «Вы на месте» (по близости к точке POI).

### Сценарий C — Инерциальное ведение (фон)
- Телефон в кармане/в руке. Приложение непрерывно считает шаги, направление (азимут) и сдвигает позицию на карте. Работает всегда, между фото-засечками.

### Сценарий D — Сбор базы (внутренний, для команды)
- Отдельный режим в приложении: съёмка эталонных фото корпусов и зданий кампуса с автоматической записью GPS-координат и угла компаса в EXIF.
- Эти фото — сырьё для офлайн-базы векторов, которая упаковывается в APK.

## 3. Архитектура системы (всё внутри одного APK)

```
[ Камера ] ──► [ Нейросеть-эмбеддер ] ──► [ Поиск по базе векторов ] ──► Координаты здания + уверенность
                                                                                │
                                                                                ▼
[ Датчики ] ─► [ Шагомер + Компас ] ────────────────────────────────► [ Фильтр частиц ] ──► Позиция на карте
                                                                                │
                                                                                ▼
                                                       [ Роутер по графу кампуса ] ──► Маршрут до корпуса
```

### Модуль 1. Офлайн-база ориентиров (`assets`)
- Фотобаза территории МАИ, собранная командой (цель: минимум 3 сезона — осень, зима, весна; для MVP допускается 1 сезон).
- В APK хранятся не фотографии, а **векторы-отпечатки** (256–512 чисел на точку) + таблица координат: ~4 МБ на 2 000 точек.
- Каждый вектор привязан к: широте, долготе, азимуту съёмки (из EXIF).
- Дополнительно: **граф маршрутов** кампуса (узлы = перекрёстки дорожек/входы, рёбра = проходы) и **список POI** (корпуса 1–8, входы, столовая и т.д.).

### Модуль 2. Компьютерное зрение (зона ML-инженера)
- Лёгкая CNN-эмбеддер (MobileNetV3 / EfficientNet-Lite / MixVPR, 15–30 МБ) через `tflite_flutter` или `onnxruntime_flutter`.
- Инференс 30–70 мс на устройстве; поиск ближайшего вектора в базе < 2 мс.
- Выход: координаты здания + оценка уверенности. При низкой уверенности — **отказ** (просим снять другой ракурс), а не ложная позиция.

### Модуль 3. Инерциальное счисление (зона инженера алгоритмов)
- Чтение акселерометра, гироскопа, магнитометра (`sensors_plus`, `flutter_compass`).
- Детекция шагов по пикам ускорения; оценка длины шага; азимут движения.
- Типичная ошибка: 2–5 % дистанции → через 50–150 м нужна повторная фото-засечка.

### Модуль 4. Фильтр частиц (ядро комплексирования)
- ~1 000 частиц-гипотез о позиции.
- Каждый шаг: сдвиг всех частиц вперёд на оцененную длину шага по азимуту (+ шум).
- Удачное фото: взвешенное стягивание частиц к распознанному зданию с учётом уверенности.
- Выход: центр облака + радиус неопределённости → на карту (ореол точности) и в триггер «попросить новое фото».

### Модуль 5. Роутер по кампусу (новый, обязателен для сценария B)
- Простейший алгоритм кратчайшего пути (Дейкстра/A*) по графу дорожек кампуса.
- Вход: текущая позиция фильтра частиц + выбранный POI. Выход: полилиния маршрута на карте + остаток дистанции.
- Отслеживание отклонения от маршрута: если пользователь сходит с пути, маршрут перестраивается от новой позиции.

## 4. UI/UX

### Главный экран (карта + навигация)
- Офлайн-карта района МАИ: улицы, дорожки, контуры корпусов (`flutter_map` + растровые тайлы OSM зум 16–18 из `assets`, ~10–20 МБ, выгрузка через MOBAC/SAS.Planet).
- Стрелка пользователя с полупрозрачным ореолом точности (растёт при ходьбе, сжимается после фото).
- При активном маршруте: полилиния маршрута, остаток дистанции, название цели.
- Крупная кнопка «Снять здание» внизу экрана.
- Плашка статуса сверху: «Позиция подтверждена» / «Ведение по шагам: точность ±15 м» / «Сфотографируйте здание для уточнения».
- Список/поиск целей: «Куда идём?» → Корпус 1 … Корпус 8, столовая, входы.

### Экран камеры (оверлей)
- Превью камеры с рамкой-подсказкой: «Наведите на фасад здания, избегая машин и людей на переднем плане».
- После снимка — автоматический возврат на карту с результатом привязки.

### Режим сбора базы (командный)
- Отдельная кнопка (в debug/настройках): съёмка эталонных фото с записью GPS + компаса в EXIF.

## 5. Технологический стек

| Компонент | Инструменты | Зачем |
|---|---|---|
| Основа приложения | **Flutter (Dart)** | Быстрая генерация кода, одна кодовая база, сборка `flutter build apk --release` |
| Офлайн-карта | **`flutter_map`** + MOBAC/SAS.Planet | Растровые тайлы OSM кампуса МАИ из assets |
| ML на устройстве | **`tflite_flutter`** (или `onnxruntime_flutter`) | Локальный запуск эмбеддера без сети |
| Сенсоры | **`sensors_plus`** + **`flutter_compass`** | Шаги, азимут, повороты |
| Камера/метаданные | **`camera`** + **`native_exif`** (или `geolocator`) | Съёмка + запись GPS/азимута в EXIF при сборе базы |
| Стартовые данные | Mapillary API / MSLS + своя съёмка | Первичный тест ML-поиска; целевая съёмка кампуса МАИ |

## 6. Структура репозитория (целевая)

```
mai-navigator/
├── PRODUCT.md              # этот файл — контекст продукта
├── README.md               # короткое описание + как собрать
├── docs/
│   ├── architecture.md     # детали архитектуры и алгоритмов
│   ├── dataset-guide.md    # регламент сбора фотобазы кампуса
│   └── roadmap.md          # этапы и дедлайны
├── app/                    # Flutter-приложение
│   ├── lib/
│   │   ├── core/           # фильтр частиц, PDR (шагомер), роутер
│   │   ├── ml/             # инференс эмбеддера, поиск по базе
│   │   ├── ui/             # экраны: карта, камера, сбор базы
│   │   └── data/           # загрузка assets-базы, POI, граф
│   ├── assets/
│   │   ├── map/            # тайлы карты
│   │   ├── db/             # векторы + координаты (бинарный/JSON)
│   │   └── model/          # tflite/onnx модель эмбеддера
│   └── pubspec.yaml
├── tools/                  # офлайн-утилиты: генерация векторов из фотобазы,
│                           # построение графа маршрутов, выгрузка тайлов
└── dataset/                # сырые фото базы (LFS / отдельное хранилище, НЕ в git целиком)
```

**Правила репозитория:**
- Сырые фото датасета в git не коммитим (большие файлы) — только вектора и метаданные; фото — в облако/LFS.
- Вся база и модель — в `assets`, приложение собирается одной командой и работает автономно.
- Ветвление: `main` (стабильный) + feature-ветки; PR с описанием, к каким модулям относится.

## 7. Дорожная карта (MVP)

| Этап | Что делаем | Критерий готовности |
|---|---|---|
| **0. Репозиторий** | GitHub repo, Flutter-проект, PRODUCT.md, README | `flutter build apk` собирается пустой шаблон |
| **1. Каркас карты** | Офлайн-карта МАИ из assets, маркер позиции (статичный) | Карта открывается офлайн, тайлы рисуются |
| **2. Режим сбора базы** | Съёмка + EXIF (GPS, азимут), экспорт на компьютер | 200–500 фото кампуса с координатами |
| **3. ML-пайплайн** | tools: фото → векторы → база; инференс в приложении | Фото корпуса распознаётся в тестах, top-1 точность ≥ 80 % |
| **4. Шагомер (PDR)** | Детекция шагов, азимут, дистанция по датчикам | На прогулке ~100 м ошибка ≤ 5 м |
| **5. Фильтр частиц** | Комплексирование фото + шагов, ореол точности | Позиция стабильно движется, ореол сжимается после фото |
| **6. Роутер + POI** | Граф кампуса, «Веди до корпуса N», перестроение | Маршрут строится и ведёт до цели |
| **7. Полевой тест** | Прогулка по кампусу без GPS/сети | Сценарий A+B проходит целиком |

## 9. Открытые вопросы (решить до этапа 3)

1. **Модель-эмбеддер:** брать предобученную (MobileNetV3/EfficientNet-Lite) или файнтюнить MixVPR на своём датасете? *(MVP: предобученная без файнтюна.)*
2. **Граница территории:** какие корпуса и дорожки МАИ входят в MVP-периметр? (нужна карта-схема кампуса с POI)
3. **Внутренние помещения:** в MVP — только улица, навигация внутри зданий не делаем.
4. **Сезонность датасета:** MVP — один сезон; проверка деградации зимой и решение о докате.
5. **Формат базы векторов:** бинарный файл (float32 + заголовок) vs JSON — определиться на этапе 3.
